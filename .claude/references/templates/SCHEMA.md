# Context Schema

Defines the canonical format for `CONTEXT.md`.
This file is generated by the `context-harvester` skill and automatically injected
via platform instructions (`opencode.json`, `.github/copilot-instructions.md`, `CLAUDE.md`).

---

## CONTEXT.md Format

**Maximum length:** 150 lines total.
**Location:** Project root (`CONTEXT.md`)

### Required Sections

```markdown
## Project Overview

1-3 sentences: what this project is, who it serves, current lifecycle stage (greenfield/brownfield).

## Stack

- **Language:** C# 12 / .NET 8
- **Framework:** ASP.NET Core Minimal APIs
- **Database:** PostgreSQL via EF Core
- **Orchestration:** .NET Aspire
- **CI/CD:** GitHub Actions
- **Cloud:** Azure Container Apps

## Patterns

- Vertical Slice Architecture with CQS
- Modular Monolith (bounded contexts as modules)
- ErrorOr for result-oriented error handling
- MediatR for command/query dispatch

## Decisions

| Date | Decision | Rationale |
|------|----------|-----------|
| 2025-01-15 | VSA over Clean Architecture | Simpler navigation, less ceremony for team size |
| 2025-02-01 | PostgreSQL over SQL Server | Cost, Linux-native, team familiarity |

## Constraints

- Must deploy to Azure Container Apps (organizational mandate)
- Team of 4 developers, 1 junior
- No external message broker initially (in-process events only)
- Budget: standard tier only
```

### Section Guidelines

| Section | Max Lines | Purpose |
|---------|-----------|---------|
| Project Overview | 5 | Quick orientation for any skill/agent |
| Stack | 15 | Technology choices — enables stack-specific skill routing |
| Patterns | 10 | Architecture patterns in use — prevents conflicting suggestions |
| Decisions | 20 | Key ADRs in compact form — prevents re-litigating past choices |
| Constraints | 10 | Hard limits — prevents impossible suggestions |

---

## Partial Context Loading

Skills can declare which CONTEXT.md sections they need via the optional `context-sections`
field in their YAML front-matter:

```yaml
---
name: dotnet-arch-vsa
context-sections: [Stack, Patterns, Constraints]
---
```

### Loading Rules

1. **If `context-sections` is specified:** Load only the listed sections from CONTEXT.md
2. **If `context-sections` is omitted:** Load the full CONTEXT.md (all sections)
3. **If `CONTEXT.md` does not exist:** Suggest running `context-harvester` but do not block execution

### Section Names (valid values for `context-sections`)

- `Project Overview`
- `Stack`
- `Patterns`
- `Decisions`
- `Constraints`

### Token Budget Guidance

| Scenario | Estimated Tokens |
|----------|-----------------|
| Full CONTEXT.md (150 lines) | ~500 tokens |
| Single section (avg 10 lines) | ~40 tokens |
| Typical skill load (2 sections) | ~80 tokens |

The partial loading system reduces context overhead by ~60% for skills that only need
stack and pattern information.
