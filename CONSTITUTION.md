## Architecture

### Architectural Style

**Decision:** Modular Monolith + VSA+CQS (ADR-0004) — avoids microservices complexity while keeping modules independently evolvable behind clean vertical slices.

### Layers / Slices

| Layer | Responsibility | May Reference |
|-------|---------------|---------------|
| Domain | Entities, value objects, domain events, invariants | Nothing (framework-free) |
| Application | Use cases (Commands/Queries via MediatR), FluentValidation | Domain only |
| Infrastructure | EF Core repositories, CAP event publishers, email | Application + Domain |
| API | Minimal API endpoints, IFeatureModule registration | Application (via MediatR dispatch) |

### Pattern Catalog

| Pattern | When to Use | Example |
|---------|-------------|---------|
| Command + Handler | Write operations that change state | `CreateTodoCommand` / handler |
| Query + Handler | Read operations | `GetTodosQuery` / handler |
| Domain Event | Cross-module side effects (via CAP) | `TodoCompletedEvent` → Notifications |
| IFeatureModule | Module self-registration with DI | `TodosModule.Install(builder)` |
| Caching Behavior | Cross-cutting cache via MediatR pipeline | `ICacheRequest` / `CachingBehavior` |
| Validation Behavior | Cross-cutting FluentValidation via pipeline | `ValidationBehavior` |
| Result<T> | Explicit error propagation without exceptions | `Result.Ok(value)` / `Result.Fail(error)` |

### Dependency Rules

- Domain MUST NOT reference any framework (no EF, no MediatR)
- Application MUST reference Domain only
- Infrastructure MUST NOT be referenced by Domain or Application
- Cross-module communication MUST go through `Contracts` events only — never direct type references between modules
- New patterns MUST be documented with an ADR before merging
- No direct `DbContext` access outside the Infrastructure layer

### ADRs

See [ARCHITECTURE.md](./ARCHITECTURE.md) for the full ADR index.

- ADR-0001: Record architecture decisions
- ADR-0002: Data Access Strategy (EF Core commands, Dapper queries)
- ADR-0003: Aspire as base technology
- ADR-0003: global.json for SDK version pinning
- ADR-0004: Central Package Management
- ADR-0004: EditorConfig for code style
- ADR-0004: Modular Monolith
- ADR-0005: Central Package Management (confirmed)
- ADR-0005: Testing Strategy
- ADR-0006: Domain-Driven Design

### Compliance Rules

- New features MUST follow the module vertical-slice structure (Application/Domain/Infrastructure)
- Cross-module references MUST go through `Contracts` events
- New patterns MUST be documented with an ADR
- Domain layer MUST remain framework-free
- `Directory.Packages.props` MUST be the single source of NuGet versions — no `Version=""` on `<PackageReference>` items

## Quality Assurance

### Test Strategy

**Pyramid:** Unit (fast, many) → Integration (module-level) → Architecture (rules) → E2E (journeys)
**Philosophy:** test behaviour, not implementation; favour integration tests for use cases

### Coverage

- Floor: 80% on Domain + Application layers
- Exclude: generated code, DTOs, configuration, `GlobalUsings.cs`

### Test Types

| Type | Scope | Tools | When |
|------|-------|-------|------|
| Unit | Domain entities, Application handlers | xUnit + Shouldly, Builder pattern | Every PR |
| Integration | Module endpoints + DB | WebApplicationFactory + Testcontainers + Respawn | Every PR |
| Architecture | Layer dependency rules | NetArchTest | Every PR |
| E2E | Full user journeys via browser | Playwright + Aspire testing | Merge to main |

### Naming Convention

**Pattern:** `Should_<expected>_When_<scenario>`

### Testability Rules

- Domain entities MUST be testable without infrastructure
- Application handlers MUST be testable with in-memory fakes for dependencies
- Integration tests MUST use Testcontainers for DB isolation + Respawn for reset between tests
- No `Thread.Sleep` — use proper async/await and polling
- Flaky tests MUST be quarantined within 24 hours

### Compliance Rules

- New public methods in Domain/Application MUST have unit tests
- New API endpoints MUST have integration tests
- Critical business logic MUST have > 80% branch coverage
- Flaky tests MUST be quarantined within 24h

## Security

### Threat Model (STRIDE)

| Threat | Asset | Mitigation | Priority |
|--------|-------|-----------|----------|
| Input injection | API endpoints | FluentValidation on all Commands; parameterised EF queries | 🔴 High |
| Spoofing | API endpoints | Authentication layer required *(open gap — see below)* | 🟡 Medium |
| Information disclosure | Error responses | ProblemDetails middleware — no stack traces in production | 🟡 Medium |
| Denial of service | Event bus | CAP retry limits + dead-letter queue handling | 🟡 Medium |
| Tampering | Domain events | Events are immutable value types in Contracts; no mutation after publish | 🔵 Low |

### Authentication

**Strategy:** Not yet defined *(open architectural decision — see Open Questions)*
All new endpoints SHOULD require authentication once an auth strategy is adopted.

### Authorization

**Model:** Not yet defined — follows auth strategy decision

### Data Protection

- No PII currently stored (todos are non-sensitive)
- Secrets MUST use Key Vault references in deployed environments
- Connection strings MUST NOT appear in source code or logs
- `appsettings.Development.json` MUST NOT contain production secrets

### OWASP Top 10 Mitigations

| # | Risk | Mitigation |
|---|------|-----------|
| A01 | Broken Access Control | Auth strategy required (open gap) |
| A03 | Injection | FluentValidation + parameterised EF queries |
| A05 | Security Misconfiguration | ProblemDetails hides internals; structured secrets |
| A09 | Security Logging | OpenTelemetry + Seq captures all requests |

### Supply Chain Security

- Central Package Management (`Directory.Packages.props`) limits version surface
- Dependabot or equivalent SHOULD be enabled on the repository
- Critical CVEs MUST be patched within 48 hours

### Compliance Rules

- All user input MUST be validated (FluentValidation on all Commands)
- Secrets MUST NEVER appear in logs or API responses
- ProblemDetails MUST be used for all error responses in production
- Critical CVEs MUST be patched within 48h
