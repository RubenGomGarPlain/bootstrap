## Business Analysis

### Domain Model

| Bounded Context | Core Entities | Relationships |
|----------------|---------------|---------------|
| Todos | `Todo` (Id, Title, Completed) | emits `TodoCreatedEvent`, `TodoCompletedEvent` via CAP |
| Notifications | No owned entities (reactive) | consumes events from Todos → email + SignalR push |
| Contracts | `TodoCreatedEvent`, `TodoCompletedEvent`, `TodoCompleted` | shared kernel — cross-module stable API |

4. **Platform & Observability** — Local dev, dashboards, and telemetry work out of the box via Aspire

## Architecture

### Architectural Style

**Decision:** Modular Monolith — avoids microservice operational complexity while maintaining bounded-context isolation and enabling future extraction if needed. (ADR-0004)

### Layers / Slices

| Layer | Responsibility | May Reference |
|-------|---------------|---------------|
| Domain | Aggregates, entities, value objects, domain events, invariants | Nothing (framework-free) |
| Application | Commands, Queries, MediatR handlers, application services | Domain only |
| Infrastructure | EF Core, CAP, Redis, migrations, external integrations | Application, Domain |
| Api | Minimal API endpoints, module registration, middleware | Infrastructure, Application |
| BuildingBlocks | Shared CQRS primitives, DomainEvents base, Cache helpers | Domain primitives only |
| Contracts | Cross-module event types (shared kernel) | Nothing |

### Pattern Catalog

| Pattern | When to Use | Example |
|---------|-------------|---------|
| CQRS (MediatR 12) | All writes → Command handler; all reads → Query handler | `CreateTodo`, `GetTodos` |
| Rich Domain Model | Aggregate owns invariants; raises events internally | `Todo.CompleteTodo()` raises `TodoCompletedEvent` |
| Domain Events + CAP outbox | Cross-module async communication | Todos emits → Notifications consumes |
| Hybrid data access | EF Core for writes/commands; Dapper for complex queries | ADR-0002 |
| Testcontainers | Integration tests requiring real infrastructure | `Testcontainers.PostgreSql` |
| ArchUnit.NET | Architecture fitness functions as code | Layer dependency tests |

### Dependency Rules

- Modules MUST NOT reference each other directly — use `Contracts` project for shared event types
- Domain layer MUST be framework-free (no EF annotations, no MediatR references, no ASP.NET)
- Application layer MUST NOT reference Infrastructure directly
- New cross-module relationships MUST be documented in `CONTEXT-MAP.md` and require an ADR
- `Contracts` event types are a stable public API — breaking changes require an ADR

## Quality Assurance

### Test Strategy

**Pyramid:** Unit (base) → Integration → Functional → Architecture → E2E (top)
**Philosophy:** Tests document behaviour; architecture tests are a CI gate, not an afterthought

### Coverage

- Floor: 80% (Domain + Application layers)
- Exclude: generated migrations, EF snapshots, DTOs, configuration files

### Test Types

| Type | Scope | Tool | When |
|------|-------|------|------|
| Unit | Domain aggregates, Application handlers | xUnit + Builder pattern | Every PR |
| Integration | Infrastructure (DB, cache, messaging) | xUnit + Testcontainers | Every PR |
| Functional | Full HTTP stack per module | WebApplicationFactory | Every PR |
| Architecture | Layer isolation, module isolation | ArchUnit.NET | Every PR (CI gate) |
| E2E | Full stack (SPA + API) | Playwright + Aspire | Release / smoke |

### Naming Convention

**Pattern:** `Should_<expected>_When_<scenario>`

### Testability Rules

- Commands and Queries MUST be testable without HTTP (pure handler unit tests)
- Domain entities MUST expose factory methods; constructors MUST be protected/private
- Integration tests MUST use Testcontainers — no mocked infrastructure at integration tier
- Flaky tests MUST be quarantined within 24 hours

### Compliance Rules

- New public Domain + Application methods MUST have unit tests
- New API endpoints MUST have integration tests
- Critical business logic MUST have >80% branch coverage
- ArchUnit violations MUST block merge

## Security

### Threat Model (STRIDE)

| Threat | Asset | Mitigation | Priority |
|--------|-------|-----------|----------|
| Spoofing | API endpoints | Auth strategy required (open concern) | High |
| Tampering | Todo data | Domain invariants; EF concurrency tokens | Medium |
| Repudiation | Mutations | Structured audit logs via OpenTelemetry | Medium |
| Information Disclosure | API responses | No PII in todos today; structured logging must never include secrets | High |
| Denial of Service | RabbitMQ / CAP pipeline | Aspire health checks; CAP retry policies | Medium |
| Elevation of Privilege | Module layer boundaries | ArchUnit tests enforce isolation | Medium |

### Authentication

**Strategy:** Not yet defined — required ADR before production. Candidates: Azure Entra ID (JWT), Keycloak, or lightweight API key for internal use.

### Authorization

**Model:** Not yet defined — will follow auth ADR.

### Data Protection

- No PII is stored in the current domain model (todos contain only Title + Completed state)
- Secrets MUST NOT appear in logs or API responses
- Connection strings and service credentials MUST be injected via Aspire resource bindings (never hardcoded)

### OWASP Top 10 Mitigations

| # | Risk | Mitigation |
|---|------|-----------|
| A01 | Broken Access Control | Auth ADR required; all endpoints to require auth |
| A02 | Cryptographic Failures | TLS enforced; no sensitive data in transit unencrypted |
| A03 | Injection | EF Core parameterised queries; Dapper with parameters |
| A05 | Security Misconfiguration | Aspire resource bindings; no secrets in config files |
| A06 | Vulnerable Components | Central Package Management (`Directory.Packages.props`) — audit regularly |
| A09 | Logging & Monitoring Failures | OpenTelemetry + Seq; structured logging always on |

### Supply Chain Security

- Central Package Management locks all NuGet versions in `Directory.Packages.props`
- Critical CVEs in direct dependencies MUST be patched within 48 hours
- `global.json` pins SDK version — no implicit SDK upgrades

### Compliance Rules

- All API endpoints MUST require authentication (pending auth ADR)
- All user input MUST be validated at the domain boundary (ArgumentException / domain invariants)
- Secrets MUST NEVER appear in logs or responses
- Critical CVEs MUST be patched within 48 hours
